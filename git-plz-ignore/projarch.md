# BESS Laboratory - Architecture Map

## Product

This checkout is a Flask BESS sizing, PPO/PPO2 training, dispatch, checkpoint benchmarking, Live Runs, and Shadow Running laboratory.

The only runnable learned controller families are **PPO** and **PPO2**. `bess.agents.SUPPORTED_POLICY_ALGORITHMS = {"ppo", "ppo2"}` is the shared source-of-truth allow-list. No-BESS and Oracle are evaluation references, not controller families.

PPO uses the canonical seven-eye `BrainEnv` in `bess/core/bess_env.py`. PPO2 deliberately keeps its separate senior-reference `PPO2Env`: fixed 15-minute data, 96 native steps/day, and its own 17-input contract, trainer, inference wrapper, Oracle, and scorer. Do not merge PPO2 into BrainEnv when changing generic PPO behavior.

Heavy or authoritative run/checkpoint history may come from another machine. Local `runs/`, `shadow/`, caches, and checkpoints are runtime artifacts, not architecture truth.

## Shared configuration rule

Battery/tariff/timebase configuration is owned by `bess/core/config.py`, not by a controller. `BESSConfig` is used by common billing, training config construction, dispatch, BrainEnv, and the PPO2 reference environment through their existing attribute contract.

Do not put generic battery, tariff, safety, or timestep configuration back inside an agent module. Controller deletion must never be able to break core configuration again.

## Canonical PPO / BrainEnv data flow

```text
DayData / MonthData
 -> build_brain_episode(...)
 -> one BrainEpisode containing every native timestep in supplied MonthData
 -> BrainEnv.reset() returns first seven-eye observation
 -> PPO requests one action
 -> caller may hold that action across N native BrainEnv steps
 -> per native step: horizon projection (when configured) -> BESS physics -> meters -> costs -> savings reward
 -> next observation
 -> episode done only after all BrainEpisode timesteps are consumed
```

`BrainEpisode` is not hardcoded to 30 days or 96 steps/day. `build_brain_episode()` derives `steps_per_day` from supplied arrays, verifies config timestep matches that resolution, and flattens all supplied days into one continuous episode.

At default `dt = 0.25` hours, native resolution is 15 minutes and a complete day has 96 native steps. A 30-day MonthData therefore has 2880 native BrainEnv transitions; a 31-day month has 2976; a 28-day month has 2688.

Policy decisions are a separate clock from native transitions. `native_steps_per_action()` requires the control interval to be an exact native-step multiple and `step_brain_control()` holds one requested action across that many native `BrainEnv.step()` calls. With 15-minute physics and 30-minute control, a 30-day episode still has 2880 native transitions but only 1440 policy decisions.

Each owned `BrainEnv.step()` returns timestep savings reward plus cumulative monthly savings. `done=True` is emitted only at the end of the whole episode. Generic BrainEnv episodes have no terminal-SOC target or horizon projection. `make_brain_env()` starts them at configured `SOC_min` unless a caller explicitly supplies another initial SOC; PPO training/validation/test, generic dispatch/replay, and no-BESS traces therefore all start from the minimum SOC by default.

## PPO2 playing field

PPO2 is intentionally independent from canonical BrainEnv semantics. `train_ppo2_dataset.py` uses `PPO2Env`, exactly 96 steps/day, 15-minute native/control intervals, its senior-reference 17-input observation, decomposed critics, and the private PPO2 Oracle/scorer. PPO2 now shares the project-wide episode-start rule: when no explicit `soc_init` is supplied, `PPO2Env` starts at configured `SOC_min`. Its default rollout constant remains `96 * 30`.

Dispatch and benchmarking identify PPO2 through checkpoint metadata (`reference_env = "ppo2_senior_15m_v1"`) and instantiate `PPO2InferenceAgent` + `PPO2Env`. PPO2 checkpoints are incompatible with non-15-minute tournament data and must be reported as a playing-field incompatibility, not as an unsupported algorithm.

## Timebase and billing

Generic PPO time resolution is derived from `dt`; do not assume 15 minutes. `steps_per_day_from_dt()` requires the timestep to tile 24 hours exactly. The fixed demand meter is clock-aligned to non-overlapping 30-minute windows, so its native sample count changes with data resolution.

`validate_control_interval_minutes()` requires a PPO policy control interval to be at least as coarse as native data, an exact native-step multiple, and a divisor of both 30 minutes and 24 hours.

PPO2 is the explicit exception: its reference contract is fixed at 15 minutes.

## Training behavior

`training_launcher.py` supports exactly PPO and PPO2. Unknown or removed algorithm names are rejected before launch.

**IQ-46/IQ-47 real-data holdout mode:** generic `train_ppo_dataset.py` no longer reuses the same exported CSV rows for training, validation, and final test. The launcher/UI expose validation/test **calendar-month counts** (default 1 each). IQ-46 first split on `YYYY-MM` boundaries but accidentally treated an incomplete trailing month as a valid billing month; the remote `ppo-iq-46-real-data-no-cheating` dataset was only 282 days (`2026-01-01` through `2026-10-09`), so its final test was the 9-day fragment `2026-10-01` through `2026-10-09` and is not a valid monthly-billing benchmark. IQ-47 fixes that benchmark bug without changing learner mechanics: only calendar months containing every date from day 1 through the real month end are eligible for train/validation/test. Incomplete leading/trailing edge fragments are ignored and explicitly reported; an incomplete internal month is rejected as malformed data rather than silently skipped. A normal January-through-December one-year CSV with the default 1/1 holdouts uses January-October for training, November for validation, and December for unseen test. Validation remains deliberately available for Oracle-BC epoch selection and Champion selection; the final test month(s) are never used for learning or Champion promotion. `p_ref_kw` is derived from training only, so future validation/test peaks cannot leak into policy normalization/reference scaling. Generic PPO still disables load/PV augmentation. PPO2 keeps its separate calendar-month split behavior unless its explicit fit-test checkbox is enabled.

**Generic PPO Training UI contract:** `bess/core/settings.py` is the single source of truth for project-tunable generic-PPO defaults through `PPO_TUNABLE_DEFAULTS`. `main.py` passes that map into `web/templates/index.html`; the Training UI visibly exposes and submits every project-tunable generic-PPO training control rather than relying on hidden runner constants: steps, seed, gamma/lambda, learning rate, adaptive-exploration LR multiplier, PPO clip, PPO epochs, minibatch, entropy/value coefficients, target KL, actor/critic gradient clips, hidden units, recurrent-GRU enable, recurrent sequence length, raw initial `log_std`, post-BC PPO-start `log_std`, validation cadence, rejection/reset patience, Champion re-anchor enable, fresh-Adam-on-re-anchor enable, live-critic-on-re-anchor preservation enable, infeasible-action mismatch shaping scale, Oracle-BC enable/max epochs/learning rate/minibatch/target MSE, logging cadence, Torch CPU thread count, plus the already-visible device selector. `training_launcher.py` validates these payload values and forwards them as explicit CLI arguments; `train_ppo_dataset.py` applies them and records the resolved values in checkpoint metadata/training reports. Brain7 observation semantics, the fixed 30-minute generic-PPO control contract, `REANCHOR_SCOPE = "full_state"`, reward/accounting units, numerical-stability guards, and the locked sizing/economic/environment parameters are architectural contracts rather than GUI tunables and remain unchanged. Custom hidden width and recurrent architecture metadata are saved in PPO checkpoints; `PPOAgent.load()` rebuilds the matching feed-forward or recurrent actor/critic shell and still infers legacy feed-forward widths when metadata is absent, so IQ-29-era and older PPO checkpoints remain loadable. The scalar training defaults now follow the IQ-45 lineage: base `log_std = -1.5`, mismatch shaping `0.10`, GAE `lambda = 0.999`, rejection patience 1, full-state Champion re-anchors, and fresh Adam; IQ-45's fixed midpoint rescue is trainer logic rather than another scalar knob. IQ-29 changes the exploration architecture instead of another scalar knob: generic PPO keeps that scalar `log_std` as a learned base and adds a tiny Brain7-conditioned `log_std_delta` MLP (hidden width derived as `max(8, hidden_size // 4)`, so the default 64-wide actor gets a 16-unit exploration helper). Its bias-free final layer is initialized to exact zero under a forked Torch RNG, preserving the old initial action distribution and sampling RNG while allowing PPO to learn state-dependent exploration later; the existing scalar `log_std` remains the sole exact global exploration offset so the new helper cannot duplicate/amplify that global degree of freedom. The later IQ-27 critic-preservation option remains exposed in the UI for experimentation but defaults OFF.

`train_ppo_dataset.py` uses canonical seven-eye BrainEnv via `make_brain_env()` and `step_brain_control()`. IQ-46 restores chronological calendar-month training episodes with `training_common.month_blocks(..., minimum_days=1)`: every training day is retained, BrainEnv and recurrent state reset at each billing-month boundary, and the trainer rotates through those months in chronological order. A PPO update is performed at each month terminal boundary, preserving the IQ-45-style roughly-one-month rollout/update geometry instead of concatenating an entire year into one monster rollout. The rollout buffer is sized for the largest training month and may update early on shorter months. Oracle teacher replay also processes every training month separately; recurrent actor/critic BC hidden state resets per month, and critic discounted return-to-go resets per month so future-month rewards cannot leak backward across billing boundaries. Validation/test are separate chronological holdout blocks and are never inserted into training rollouts or Oracle teacher samples.

IQ-43 restored IQ-41-style immediate Champion re-anchoring and changed critic regression from squared-error MSE to unit-beta Smooth-L1/Huber via `_critic_value_loss()` in `bess/agents/ppo_agent.py`, used by both recurrent and feed-forward PPO updates. It reproduced IQ-41's Champion almost exactly (144.342831M VND, 2.00838% Oracle gap versus IQ-41 about 144.342466M VND) while shrinking the final raw critic gradient from about 94.28 to 2.86; explained variance remained about 0.151, so the robust loss fixed gradient scale but did not improve economic IQ. IQ-44 kept the robust critic but scaled Huber's transition by each minibatch return standard deviation (minimum beta 1.0). It completed at 144.342139M VND (+21.6298651%, 2.0078887% Oracle gap), only about 327.5 VND better than IQ-41 and about 692.7 VND better than IQ-43, with the same 2 accepted / 275 rejected / 275 reset geometry and the same winning step 338,400. Final explained variance stayed about 0.1503 and raw critic gradient about 2.50. More importantly, IQ-41/IQ-43/IQ-44 candidate curves are nearly identical around the winner even though their critic losses differ. That matches the implementation: rollout advantages are computed before optimizer work, actor and critic parameter paths are separate, and patience-1 full-state re-anchors discard critic learning after almost every rejected update. Critic-loss tuning therefore cannot materially reshape most one-shot actor candidates. IQ-45 keeps IQ-44's critic behavior and moves the experiment to candidate mechanics: when a full PPO candidate is rejected exactly when the existing re-anchor rule would discard it, the trainer now performs one deterministic rescue evaluation at the exact 50% network midpoint between Champion and challenger. If that midpoint is cheaper it becomes Champion; otherwise the normal full-state/fresh-Adam re-anchor proceeds. The midpoint is a fixed algorithmic half-step rather than another scalar training knob, and adds at most one extra validation for a reset-bound rejected update. The completed full-overlap IQ-45 fit benchmark reached 144.119246M VND (+21.7508839%, 1.85037% above the wear-inclusive Oracle) with 7 midpoint rescues; it is the final deliberately-cheating fit benchmark. IQ-46 keeps IQ-45's learner, midpoint rescue, Brain7, recurrent architecture, 30-minute control, locked PPO/economic/environment settings, actor BC 300, critic BC 100, and PPO2 behavior unchanged, but removes the debug data leakage: chronological training/validation/test are disjoint, `p_ref` uses training only, and multi-month training/BC resets state/returns at billing-month boundaries. Because demand billing is monthly, that 9-day test is diagnostic only, not the first trustworthy unseen-month IQ. ## Checkpoint tournament

Benchmarking is **checkpoint-centric**, not algorithm-seat-centric. Users select compatible `policy_*.pt` fighters. Multiple PPO checkpoints with different seeds/settings may fight each other; PPO and PPO2 may fight when the selected dataset is compatible with both.

The tournament runs:

```text
No-BESS reference
selected PPO/PPO2 .pt fighters
Oracle reference
 -> common tournament summaries / leaderboard / detective views
```

No learned controller is hardcoded as a benchmark reference. A learned method participates only through a selected supported checkpoint. The allow-list is PPO/PPO2 only.

## Dispatch, Live, and Shadow

- Dispatch lists and runs only PPO/PPO2 checkpoints. Old removed-algorithm `.pt` artifacts may remain on disk but are not runnable.
- Live Runs snapshot the selected CSV and reveal No-BESS plus one selected PPO/PPO2 policy day-by-day. Sessions are in-memory only.
- Shadow Running persists No-BESS plus one selected PPO/PPO2 policy against CSV or ThingsBoard measured data. It never emits real battery commands.
- Shadow persistence lives in `shadow/shadow.sqlite`; daily native-resolution traces are stored in the same database.
- The current Shadow schema contains no removed-controller columns. On opening a legacy local Shadow DB with old controller-specific columns, local non-authoritative Shadow history is dropped and the current schema is recreated.
- ThingsBoard configuration is still a measured-data source. Shadow-specific controller weather planning was removed because PPO/PPO2 do not consume it. The standalone Get Weather tool remains independent.

## Source data and generated/runtime state

- `data/*.csv` are source datasets discovered by training/data helpers. Do not delete useful measurements merely because an old filename contains a removed algorithm name. `scripts/make_avg_30_day_csv.py` can derive a regenerable `<input>_avg30.csv` test dataset by averaging load/PV per native step, keeping working-day and weekend profiles separate, then emitting exactly 30 sequential days with the canonical CSV columns. It bootstraps the repository root before importing `bess.paths`, so the documented direct command `python scripts/make_avg_30_day_csv.py` works from the repository root.
- `user_data/` holds exported training inputs and regenerable Oracle cache data.
- `checkpoints/` stores learned policy/checkpoint/report artifacts; artifacts from other machines are not source architecture.
- `runs/runs.sqlite` and `runs/traces/` store persisted Dispatch run metadata/traces.
- `shadow/shadow.sqlite` stores persistent Shadow configuration/audit/traces in this checkout.
- ThingsBoard/weather connector secrets and runtime caches must not be treated as source-code configuration or exposed through public APIs.

## Architectural rules

1. The only runnable learned controller families are PPO and PPO2; use `SUPPORTED_POLICY_ALGORITHMS` instead of copying allow-lists.
2. Treat `bess/core/bess_env.py` as canonical generic PPO environment behavior.
3. Preserve PPO2's isolated fixed-15-minute `PPO2Env`/Oracle contract; do not generalize PPO2 rules to BrainEnv.
4. Benchmark learned controllers through selected checkpoints; do not add a special hardcoded learned-controller benchmark seat.
5. No-BESS and Oracle are references, not learned controller families.
6. Keep generic BESS/tariff/timebase configuration in `bess/core/config.py`, never in an agent module.
7. Distinguish native environment transitions from PPO policy/control decisions; held actions can span native steps.
8. Do not assume 96 steps/day except for 15-minute data or PPO2's explicit reference contract.
9. Do not assume a canonical BrainEpisode is exactly 30 days; its length is supplied MonthData length.
10. Keep the fixed demand-charge meter clock-aligned to non-overlapping 30-minute windows.
11. Preserve requested action versus physically executed behavior when tracing/debugging.
12. Use `bess.paths.PROJECT_ROOT` for repository filesystem anchoring.
13. Runtime artifacts from this machine are not authoritative evidence for runs produced on another machine.
14. Generic PPO real-data benchmarking must split train/validation/test on chronological calendar-month boundaries with zero overlap; validation may select BC/Champion state, but the newest test month(s) must remain unseen until final evaluation.
15. Update this map whenever code behavior, module ownership, entrypoints, persistence, or data flow materially changes.
